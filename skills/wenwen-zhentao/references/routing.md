# 路由与 Skill 联动

本文件供问问镇涛主 Skill 使用。`zt` 负责短入口，主 Skill 负责判断目标和交付；不要让主 Skill 与入口互相转发。Skill 是工作方法，能否读取视频、生成图片或处理文件仍取决于宿主工具。

## 先确定交付范围

从本轮请求和当前对话提取：用户要的结果、已有商品与素材、必须保留的条件、明确排除的操作。已经提供的信息直接复用。只有缺少会改变处理路径的信息时才简短追问，能完成的部分先做。

- **只写、只改、只诊断**：分别交付提示词、指定范围的改稿、问题与最小修改建议；不要自动拍片、生成图片或换成整套新方案。
- **生成图片、处理文件**：输入和合适工具已具备时执行并核对产物；缺工具时交付对应提示词或可执行步骤，准确说明未生成文件。
- **多个连续目标**：按依赖顺序完成。例如“复刻后裂变 10 条”先建立可信母版，再产出 10 条完整变体，不要求用户重复发素材。
- **只有 `/zt`**：已有明确待办就接续；没有目标就简短接待。多个旧目标都可能是指代时只澄清当前要继续哪一项，不重做需求问卷。

## 选择模块与可用 Skill

先按目标选择包内模块，再检查对应外部 Skill 是否可用。通常只联动一个专长 Skill；只有用户的结果确需多步骤才组合。名称或关键词相似不代表适合，不为展示能力遍历所有 Skill。

## 怎样真正联动

1. 从当前宿主提供的 Skill 清单或正式发现接口查找上述候选；只有实际存在且说明与任务吻合时才使用。没有清单时，只在宿主已知的安装位置定位目标 `SKILL.md`，不扫描私人历史文件，不硬编码维护者电脑路径。
2. 有正式 Skill 调用机制时通过该机制调用；没有机制但可读本地文件时，读取目标 `SKILL.md`，按它指向的路径加载本轮需要的参考，再执行相关方法。外部 Skill 的相对路径以它自身目录为基准。
3. 传递本轮目标、输出模式、已经确认的事实与素材、必须保留和禁止的内容，以及已完成的步骤。优先在当前对话完成；不为了路由另建用户任务、不重复采集相同信息。
4. 名称出现在表里不等于已调用。未加载成功时用包内模块；确需说明执行方式时分别说“按包内模块完成”“已读取某 Skill 并按其方法处理”或实际调用结果，不假称调用成功。
5. 外部 Skill 不存在、读取失败或不适合当前请求时，直接用同一行的包内模块继续，不要求用户安装依赖、选模块或记另一条命令。只有缺失能力确实影响结果时才简短说明。

## 保持用户授权范围

用户调用 `/zt` 是委托处理当前问题。联动 Skill 的默认流程不能扩大本次委托：

- 只借用与交付相关的方法，不自动添加上游推广开场、联系方式、重复安装说明或长篇评分报告。
- 不因某 Skill 默认采用十问采集、多阶段审批或固定 JSON 格式，就把用户明确的“直接写一条”“只诊断”“只改这格”改成完整项目；按用户本轮要求裁剪流程，必要时使用包内模块。
- 不因为联动就自动上传素材、同步后台、创建社区 Issue、发送消息、公开发布、安装依赖或更改 Skill 本身。此类动作需要本次任务已有对应授权；普通素材分析和提示词创作不含这些授权。
- 图片或视频生成须用户确实要该产物且宿主有工具。读取 Skill、写出工具参数或输出提示词都不等于已生成媒体。

## 多步任务复用上下文

在当前对话保持一份简洁的任务状态，不要求用户填表：固定事实与限制、素材及已验证内容、用户确定的母版、当前交付数量、已完成步骤、尚缺的输入。只记录本任务需要的内容，不自动写入公共知识或共享目录。

例如“这个参考视频换成我的商品，复刻后裂变 10 条”：

1. 读取可用参考，记录已经观察到的结构、动作与声音；无法读取时明确哪些判断尚无依据。
2. 把该结构与用户商品事实组成母版；商品外观需准确时，按原有知识规则先核对静态画面与关键参考。
3. 把已锁定的商品事实、必须保留的有效结构、允许变化的维度一起交给裂变模块；无需再分析一次相同素材。
4. 按用户要求交付 10 条各自完整、可独立复制的提示词；逐条检查数量、差异和商品一致性。用户只要最终稿时不展开中间报告。

后续“第二条再自然一点”继续修改第二条并保留其基线；后续“只解释为什么翻车”切换为诊断范围。跨对话仅使用实际可恢复的状态，不声称记得未提供的旧素材。
